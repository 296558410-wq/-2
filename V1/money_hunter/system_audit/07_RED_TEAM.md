# 07_RED_TEAM — 击穿钱猎手：10+ 攻击点（2026-09-06）
1. 数据偏差: 全部研究基于零售 spot 报价(DUKA/FXTM), 它不代表真实市场(内部化/ECN 分层外) → 状态: 部分解决(已声明 proxy 纪律; 未解决=无真实市场数据)
2. 选择/时间偏差: 2023-26 上行样本主导早期结论 → 已解决(跨 regime 2011-2026 补齐, D1R/MTF/T-c 被杀)
3. 成本偏差: 用报价 spread 当成本, 未计 last-look/拒单/排队/冲击 → 部分解决(标 COST_UNKNOWN/下界; 未解决=无执行通道)
4. 执行偏差: "会成交"假设未经任何真实订单检验 → 未解决(EXECUTION_GATE)
5. 多重检验/自由度: 预注册+SI 台账全链 → 已解决(设计层); 残余: 同日多任务共享同一数据(相关性未全建模) → 部分
6. 未来信息泄漏: 门禁+无前视审计 → 已解决(多轮)
7. regime 选择: 分段事后? → 已解决(T-a..d 事前分段, 无段选择)
8. 容量/流动性: 慢流程 48 仓/3.7y 无容量问题但无意义; 任何 HF 候选的容量从未测(无候选) → n/a
9. 延迟假设: 100ms+ retail 已声明 → 已解决(声明级)
10. researcher bias(想找到钱): 多次"表观正收益"被随机对照杀死(MTF/审计)——系统抗性真实存在 → 已解决
11. **我们没意识到的**: (a) "proxy 纪律"可能过度自我审查——我们拒绝用 tick_volume/毛量做任何 flow 推断, 但**毛量变化率在事件窗的异常**(即使非 signed)可能携带信息而我们因纪律从未检验 → 未解决, 零成本可测; (b) 数据缺口月(12 月)系统性缺失可能给"年频结构"研究埋坑(我们没做年频结构); (c) 微结构记忆刚开始, "采集→假设"环尚无自动分析——机器可能在积累数据但从不学习它(每日 cycle 只查健康) → 未解决(最高优先级流程漏洞); (d) 全部"无钱"结论基于 2011-2026, 但执行侧若未来成本结构变化(如 0.2bps 通道), 需要重测的不是信号而是整个 EV 表 → 已声明待解锁。
攻击总结: 致命未解决 = 执行反馈缺失 + signed flow 缺失; 流程漏洞 = 新数据无自动分析环。
